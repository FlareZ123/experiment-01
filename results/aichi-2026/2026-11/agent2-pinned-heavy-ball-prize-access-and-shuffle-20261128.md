# Twinleaf ASR146 Hisuian Heavy Ball: legitimate Prize-reveal projection **and** a genuine ignored-return shuffle defect

**Agent 2, 28 November 2026 14:02 UTC.** Pinned-source direct implementation analysis plus **two research-owned opt-in repairs**, no vendor changes, no native Store witness/CI/game/qualified field matchup.

## Two distinct execution blockers

Read the exact pinned Twinleaf implementation (`a9905a76a6c4103ba4b6cb9a49e86bad795c5c05`) in `ptcg-server/src/sets/09-sword-and-shield/set-astral-radiance/hisuian-heavy-ball.ts`, Git blob `894450a28fe12cb6291b14f301d7ea05e7b1f1b3`.

1. **Trusted Prize visibility mismatch:** when the player uses Hisuian Heavy Ball ASR146, pinned `reduceEffect` deliberately changes original face-down `player.prizes[i].isSecret` flags to **false** before creating a new `ChooseCardsPrompt` containing the same original Prize Card references. That is legitimate private observation by this *actor*, whose Item explicitly instructs them to look at their own face-down Prizes. The generic research-side `agent36-prompt-projection.cjs` checks Prize `faceUpPrize===true` instead of temporarily revealed `isSecret===false`; it therefore refuses the authentic owner-visible Basic search. Simply turning all hidden Prize cards visible in the generic projector would leak K0 information and is **not acceptable**. The proper fix is source-effect-scoped.
2. **Ignored shuffle result (pinned game-semantic bug):** the pinned Item invokes `this.shuffleFaceDownPrizeCards(player.prizes.filter(...))` in both selection branches and **ignores its return value**. The method internally shuffles a *new filtered array*, constructs another `prizePositions` array and returns that detached array. It never mutates `player.prizes` or any Prize CardList's `cards`. Consequently the supposed face-down Prize shuffle has **no effect on physical Prize positions**. That is not a strategic hypothesis; it is directly implied by the pinned source semantics. It violates Hisuian Heavy Ball's printed instruction and can yield incorrect Prize-position information in simulations. The correction is to shuffle the card payloads among the original face-down Prize CardLists, with the original slot references and flags preserved.

These are separate from the optional rank18 Squawkabilly Motivate support in `agent2-rank18-motivate-native-shape-optin-20261128.md`.

The pending prompt must belong to the physical actor, and its **detached aggregate card list** must equal, by *reference and order*, the concatenation of that actor's genuine Prize CardLists. All occupied owner Prize CardLists must already have `isSecret===false` at this exact native point; otherwise it refuses. It will **not** project opponent Prizes, reveal arbitrary K0 cards, accept a forged collector number or foreign original-60 Basic, or relax another Item's disclosure.

Opaque tokens map to native-valid Prize aggregate indices, never exposed to the policy. The rank18 policy's existing source-specific Heavy Ball choice selects the best required Basic from these owner-authorized cards. **10/10 two-seat V8 in-process regression groups, 121 assertions**, including hidden opponent Prize, still-facdown flags, taken-Prize ordering, no Basic, duplicate same printing, source/owner/shape tampering, and strict `validatePrompt` / `validateDecision`. ## Source-scoped repair 2: actual pinned Prize shuffle

`simulation/twinleaf/agent2-hisuian-heavy-ball-prize-shuffle-hook.cjs` committed [f1b7048](https://github.com/FlareZ123/experiment-01/commit/f1b7048e56a9debd535ecc40272127d132bdebf9).

Provides explicit `installPinnedHisuianHeavyBallShuffleHook({CardClass,enginePin,rng})`, refusing any engine pin other than the exact pinned revision, any source class other than original `HisuianHeavyBall` ASR146, and any compiled method without the known source signature (`faceDownPrizeCards`, `prizePositions`, `splice`). It only patches the class's *single native shuffle method*, never edits submodule source, and supports idempotent install and safe uninstall. Runtime input requires mutable Prize CardLists with boolean `isSecret`, no duplicate CardList references and exactly one card in any occupied secret Prize slot. It applies uniform Fisher–Yates to the **card objects** selected by secret occupied slots, writing them back to the **same original CardList cards arrays**. Unrevealed/face-up or empty Prize slots, slot flags, CardList identities, and card multiset remain unchanged. Injected RNG supports reproducible seeded experiments. Incompatible or malformed input fails closed, rather than silently fabricating a shuffle.

Tests `tests/2026-11/agent2-hisuian-heavy-ball-prize-shuffle-hook.test.cjs`, [45197a7](https://github.com/FlareZ123/experiment-01/commit/45197a73f86d4bb1e0a83736d45d0ed010b0ed6e), [0c13a41](https://github.com/FlareZ123/experiment-01/commit/0c13a41c95f5eb53933fb097013d277c8e796f85): faithful original detached-return behavior leaves physical slots unchanged; patched method deterministically moves unique physical Prize cards across original slots (example `A B C D` → `B C D A` under fixed `rng()=0`), with all card references conserved. Also tests face-up/empty isolation, bad pin/source/changed implementation, duplicate/multi-card Prize defensive rejection, RNG range checks, stable slot/card-array identities, no random draws for zero/one eligible prizes, idempotence/uninstall. **9/9 V8 in-process groups, 70 assertions**.

## Interpretation / required next integration

This is a **source-level demonstrated native rules defect**, with an opt-in research-side hook that is regression-tested synthetically. It is **not** yet proof that the patch works with the actual pinned TypeScript-compiled `Store` or with the production PR104 native queue. The projector and shuffle hook must remain opt-in, untouched in the vendor submodule and default shared pipeline. At the next independently authorized, isolated *no-game* test of the ASR146 action, an owner can verify real `ChooseCardsPrompt` provenance, actor-only temporary visibility, a selected and an unselected Basic path, the post-resolution **physical card-to-Prize-slot** permutation, and clone-only prompt validation. No arbitrary Prize identity should ever enter opponent observations.

Any previous simulation involving Hisuian Heavy Ball position-dependent K1 conclusions should be **treated as potentially wrong**, unless pinned-native behavior was separately repaired and the shuffle result observed in actual state. This finding does not establish candidate performance or any of the 32 Aichi matchups. The broader objective still needs one fixed legal 60 and full-source competitive games.

## Addendum — explicitly exclude already face-up Basic Prizes (14:04 UTC)

The pinned ASR146 Item searches **face-down** Prize cards, but its native `ChooseCardsPrompt` aggregation includes **all** physical Prize cards, even those permanently face-up due to another effect. The actor-safe source extension now recognizes `prize.faceUpPrize===true` as ineligible and never offers such a Basic as a native policy token, even while its temporarily revealed `isSecret` flag is false. This prevents the engine's otherwise too-wide source aggregation from creating a source-illegal selected card.
