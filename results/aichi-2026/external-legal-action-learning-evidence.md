# External 2026 Pokémon TCG agent research: transferable method, incompatible engine

**Date:** 18 October 2026. **Evidence level:** public research design comparison, not an engine integration, field performance result, or decklist.

## Public code and published findings

The public [`ymgaq/ptcg-population-rl`](https://github.com/ymgaq/ptcg-population-rl) repository (Apache-2.0; [README](https://github.com/ymgaq/ptcg-population-rl/blob/main/README.md)) accompanies the authors' [24th-place Pokémon TCG AI Battle Challenge solution](https://www.kaggle.com/competitions/pokemon-tcg-ai-battle/writeups/24th-solution-a-population-based-rl-ecosystem). Its architecture starts with a rules-driven expert that records each observation and chosen legal option. LightGBM LambdaRank learns to **rank the available legal options**, with different tree banks for MAIN vs other decisions. It then distills a GBDT teacher into a policy/value Transformer and uses self-play PPO, with seat-swapped common seeds and a Bayesian Bradley–Terry rating model. It includes *examples* for the challenge's four preset decks: Mega Lucario ex, Dragapult ex, Iono, and Mega Abomasnow ex. The public sample itself excludes its original production weights, training replays, opponent population selection and long-running leaderboard process.

Independent [`Gabriel-notme/ptcg-ai-battle-journey`](https://github.com/Gabriel-notme/ptcg-ai-battle-journey) reports the simpler legal-action semantic **GBDT ranker** as preferable in its own experiments to more ambitious value and PPO iterations, with a strict future-time held-out training split and paired games. Its raw 2026 Kaggle experiment results are *not* Expanded-matchup rates. These two sources support piloting a small, semantic action-selection method before investing in more elaborate reinforcement learning.

## Why this does not transfer as a ready-made solution

Kaggle's 2026 battle challenge uses a **different engine, action schema, officially constrained standard-format decks and card pool**. Our experiment uses an independently pinned Twinleaf implementation for 60-card paper **Black & White-onward Expanded**, with Japanese printing support gaps, source-specific search/lock semantics and missing Top 32 60s. The public Kaggle code *cannot* be declared a legal substitute for `simulation/twinleaf/` or imported pretrained model. Even its sample authors caution that the disclosed code omits replays, trained weights and parts of the actual population ecosystem. The performance cited externally is specific to those different conditions.

A foundation for local action learning is already present in `simulation/twinleaf/headless.cjs`: `captureDecisionTrace`, `decisionHandEvidence`, `selectedCardsEvidence` and `selectedOptionEvidence` record root Store decisions and prompt-resolver selections. `SimpleTacticsAi.prototype.decodeNextAction(state)` is the engine entry point currently patched by opt-in policies, while `Store.dispatch(action)` is the authoritative root transition. Existing `strictPromptValidation` and owner-search checks must remain enabled where applicable. The converter should consume **pre-action, player-visible observations and verified legal candidate options**; a post-action diagnostic clone is not an authorized source of information for live decisions.

## Minimal, falsifiable Twinleaf-native experiment

Choose an actual blocked *prompt-decision family* (for example, a ChooseCards search target with a validated public option set). Freeze an observed source 60 and a candidate fixed 60 before data collection, and freeze a small test seed schedule with both genuine starting seats. For each root decision, record: engine/research commit IDs, exact player seat, board/hand/known Prize information state `K0/K1`, currently enabled option identities, public opponent observations, option-level pre-action tactical features, and expert/policy chosen option. Never give the scorer unseen opponent hand, hidden Prize identities, or card names learned through a diagnostic **after** the decision.

Use an interpretably small scoring baseline, such as a manually weighted per-option feature scorer, with the exact same candidate/decision set as the default Twinleaf choice. A trained legal-option ranker becomes interesting only after enough independent, competent expert observations and verified option semantics exist. Pilot a **frozen held-out seed bundle**, run paired choices against baseline with identical decks and genuine turn swaps, and audit both source opponent and candidate response transcripts. A policy that increases first-turn setup frequency while degrading follow-on Prize conversion or vulnerable Bench exposure should fail the gate.

Only after this narrow task demonstrably improves **held-out game outcomes** and retains rule legality would a larger learning stack be justified. Sequential evidence must remain matchup-specific across all 32 Aichi slots, with source ranks 23/25/28 excluded from exact-list claims until acquired. Separate observational trace fidelity, action legality, game completion, decision skill, and fixed-60 performance in every report.

## Non-goals and immediate constraints

This note neither launches a Kaggle training project nor assumes the C++ competition simulator can execute Expanded printings. The best next investment may instead be qualifying adversarial scripted policies in Twinleaf, given the shared board currently records **zero competitively qualified games**. A legal-action ranker is a **possible path to strong policies**, contingent on extracting correct observation/action pairs from the source engine, sufficient quality data, and strict separation of training from evaluated games.
