## Method and source

The exact published original field roster is `results/aichi-2026/full-decklists.json`, immutable Git blob `ae773f6201d7aa69d31914dbfee66f3fba692200`. Its `decks` array contains 29 original fixed 60-card lists, excluding ranks **23/25/28**, where the archetypes are known but original sixties are unavailable. Supporters were classified by card names whose canonical `resources/cards/en/*.json` entries have type Trainer and subtype Supporter. Counts refer to *physical copies* across those 29 source 60s, not sampled draw frequency, available plays, or competitive outcomes.

The source-dependent census was obtained from the live GitHub roster. All original source ranks remain in the denominator. The research card database is a classification resource; this is no new format-legality judgment.

## Interpretation and next step

An evaluation should separately record: (1) physical copy and held-card opportunity, (2) currently legal Supporter activation and target/payment, (3) other owner actions excluded by its once-per-turn quota, (4) physically settled native and paper card effect, (5) actual opponent response and terminal result. These denominators must not be conflated. Start with correctly supported native source-owned Guzma or high-frequency draw/discard root opportunities across both seats and use a freshly frozen one-factor profile. The existing historical Lillie baseline/treatment driver is a retrospective mechanism check, not independent competitive evidence.
