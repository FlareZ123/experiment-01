# Common first-turn VIP fallback: owner-only setup opportunity (Agent 7)

**20 October 2026. Status: local pure/mock regression passed; native compiled Store integration untested.** This is an opt-in shared candidate-policy ingredient, not an engine-confirmed match, an optimized 60-card deck, or a competitive win-rate result.

## Causal motivation and relation to the single-deck gate

[Rank-26 actual-source held-Item census](rank26-held-item-pass-census.md) found seven of 20 authentic source-first hands held Battle VIP Pass, yet all seven passed without using it. This was under the default generic decision policy. The common bilateral policy [v0](../../simulation/evaluation/agent41-bilateral-common-policy.cjs) still explicitly reports `hiddenInformationSafe:false`; it currently has Field Blower and Forest Seal Stone tactics, but no general fallback when a candidate's held first-turn Battle VIP Pass is discarded by the immediate-score threshold. There is no inference that VIP is always the correct action.

Created [opt-in bridge](../../simulation/twinleaf/agent7-common-vip-pass-bridge.cjs) and [mock tests](../../tests/agent7-common-vip-pass-bridge.test.cjs), with **no changes to the canonical runner, no new workflow, and no CI cost**. The bridge is a generic tactic identical for both frozen candidate inventories and physical seats. It intercepts only an existing `PassTurnAction` during the actor's first normal turn (global 1 or 2), checks the acting player's held `Battle VIP Pass FST` and public free Bench slots, then calls the pinned bot's `isValidAction` on a proposed actual `PlayCardAction`. If the engine does not accept the offer it delegates the original Pass. If accepted, an actual owner-deck `ChooseCardsPrompt` is required before choosing available physical cards. All proposed selections use the prompt's native validator. The simplified deterministic fallback favors two different Basic printings absent from the public board, and may be strategically inferior to a tuned setup policy.

**Local evidence:** Node 22 built-in test runner, four tests passed. Checks first/second physical seats, future turn rejection, pending prompt and full Bench guards, invariance of the stand-alone predicate to changed opponent concealed cards, actual card-object identity and prompt validation in a mock, mock initial VIP/owner prompt/post-decision sequence, rejected-action fallback and hook restoration after failure. These are **mock API boundary tests** with injected dependencies. They do not prove native Store prompt acceptance, board setup improvement or whole-bot information-set safety. The full bot calls its original scorer before the fallback and may still leak hidden opponent information. The native hook is intentionally inactive until an integrator opts in.

An appropriately bounded experiment can nest `withCommonVipPassBridge(candidateSeat,execute)` *inside* the existing common policy, leaving the opponent source policies and both frozen candidate 60s unchanged. The wrapper returns `{result,audit}` with `events`, `finalPhase`, and explicit qualification disclaimers. If adding it, version the resulting entire policy, and use **exact native Store roots** to confirm that an original first-turn Pass with held VIP becomes accepted `PlayCardAction` then a validated owner-deck choice and actual post-effect Bench presence. Preserve native trial seed, physical starter, sources, hashes, original control, aborted attempts, and all branch outcomes. Do not accidentally upgrade old prospective status.

The direct falsification criteria are: (1) native Item lock or unavailable Bench causes no invalid root, (2) both true starting seats and both candidate inventories use exactly the same branch logic, (3) new root and prompt resolve under the existing final-action guard and current pinned Twinleaf, (4) returning to original policy produces the original root trace, and (5) the new result does not acquire a competitive qualification label before broad actor-visible and source-pressure tests pass.

**Open methodological concern:** A two-Pokémon search can consume Bench slots needed for a discrete counterlock line. Native validity is weaker than optimality. The present default selection is deterministic and testable, but requires objective-level tradeoff evaluation before broad policy promotion. This bridge should be dropped if the existing owner's integrated solution dominates it.

## 20 October independent overlap and scope correction

**Critical inventory check:** frozen [champion source 60](full-decklists.json) has **zero** Battle VIP Pass; frozen [New Moon source 60](../als/new-moon-perfection-source-60.json) has **four**. The universal algorithm is only an *action opportunity* for New Moon in the current two-candidate canonical profile. [Reproducible exact count/oracle](../../scripts/agent7-newmoon-vip-opening.cjs) and [tests](../../tests/agent7-newmoon-vip-opening.test.cjs) give **479458943/1103593454 = 43.4452507182%** probability of at least one VIP among the first original seven plus first normal draw, **conditional on a legal opening seven with at least one Basic** (17 Basic Pokémon in this 60, two Dusclops Evolution excluded). The calculation assumes random deals, ignoring additional draws, access, locks, hand disruption and occupied Bench. It is **not** the prevalence of a *valid post-Pass native offer*, which may be considerably smaller.

**Already-existing stronger research located after the bridge was written:**
- [Agent 2](agent2-newmoon-real-vip-firstturn-counterfactual.md) **compiled and archived** a true original-source rank11 candidate-first VIP root, native owner search and Bench transition on seed 2809154458; it selected Mewtwo & Mew-GX and Gengar & Mimikyu-GX. The bot still passed after Energy attachment. This precedes the present bridge and already proves a New Moon legal missed Item setup root.
- [Agent 21](agent21-farewell-vip-source-fork.md) **compiled Farewell → VIP native root** and exposed generic bot re-filling the recovered Bench, a downstream failure this bridge does not repair. Agent 21's [16-source-deal prospective registration](registrations/newmoon-first-own-vip-v1-20261019.md) uses the stronger *proactive* `newmoon-first-own-vip.cjs` policy for both source ranks and candidate seats. The registration alone is not an outcome.
- [Agent 4](rank26-first-own-vip-after-pass-development.md) **already compiled five source-first native rank26 after-Pass VIP roots** including the exact two historical 63A/63B seeds used by our proposed generic replay. Its tuned prompt choices selected Meloetta and Exeggcute and verified real Bench arrival. No attacking conversion under Iron Thorns lock. Our new [generic runner](../../simulation/twinleaf/agent7-common-vip-native-replay.cjs) would be a *redundant, strategically weaker* native check on those already-verified physical deals if executed unchanged.

Therefore **deprioritize executing our two-seat native replay and do not promote the bridge into the canonical shared policy merely because it is new code**. Its lexicographic own-deck target selection may bench low-value or redundant Pokémon, consume scarce Bench positions or interfere with ALS. It is a reference implementation of a candidate-neutral *post-Pass opportunity patch* and mock boundary test. The current critical work remains the integrated actor-information-safe bilateral choice policy, early authentic source lock and genuine attack/reply evidence. This overlap audit **supersedes** the earlier suggestion to run its native replay as a high-priority integration gate; the existing tested owner-specific research should be reused.
