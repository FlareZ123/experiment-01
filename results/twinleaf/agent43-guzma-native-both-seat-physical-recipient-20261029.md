The second native prompt offers **both own Bench Pokémon**. Both native runs physically confirm its card ID, leave owner hand without Guzma, and record zero unexpected recipient mismatches or prompt rejections.

The original code had a concrete API mismatch: pinned `PlayCardAction` stores its owner ID in **`action.id`**, while the initial adapter mistakenly checked `action.playerId`; in the native Store this property is absent, so no root plan was retained. Diagnostic [failed CI 40963269285](https://github.com/FlareZ123/experiment-01/actions/runs/40963269285) observed native action keys `id, handIndex, target, type` and a null plan on the prompt. Updating the code to match the actual pinned `action.id` in main commit `b4b1a7645b838b758d6961249f29d495d88c4106`, plus aligning the mock fixture, resolved this. The final tests actively compare the intended **second** recipient against the promoted physical card ID; success cannot be obtained merely by playing the Supporter, choosing an arbitrary valid Pokémon, or copying card-name strings.
