# Native owner-visible ChoosePokemon integration, default-off canonical policy

**Agent 8, 21 October 2026.** This is a **prompt-execution and actor-information-boundary** improvement. It is not a competitive-game or matchup-win result. The Aichi decision index still reports 29 of 32 exact opponent sixty-card lists and zero qualified games.

## Problem and fixed boundary

The archived five-component actor-policy audit counted **six last-chance generic ChoosePokemonPrompt invocations** across its eight selected development arms (see [previous audit](agent8-native-selectprompt-canonical-v2-20261020.md)). The fallback is the native `SimpleTacticsAi`, which has not been established as owner-information-safe or strategically competent. The new component covers only genuine native single-target Pokémon prompts and delegates unsupported cases without granting them actor-only credit.

Pinned engine: Twinleaf submodule `vendor/twinleaf`, `a9905a76a6c4103ba4b6cb9a49e86bad795c5c05`. Read the pinned `ptcg-server/src/game/store/prompts/choose-pokemon-prompt.ts` and `ptcg-server/src/game/store/actions/play-card-action.ts`. The former's `getPerspectivePlayerId()` may differ from the **answering** `playerId`; `playerType` TOP/BOTTOM are relative to the former. Native `ChoosePokemonPrompt.validate` handles count, blocked targets and target existence but does not by itself enumerate eligible side/slot geometry. Our existing research `prompt-integrity.cjs` checks that resulting targets are physically within allowed side/slot and distinct.

## Implemented

- [Actor-only adapter](../../simulation/twinleaf/agent8-actor-only-choose-pokemon.cjs), commit `8cb088063f42ab1357b2cc4219c337b9d3744a1c`. Enumerates physically populated ACTIVE/BENCH slots according to `PlayerType`, `SlotType`, perspective owner and native validator; projects an inert frozen menu with public printing, remaining HP, Energy count, printed attack names and physical relative side. `actorObservation` supplies the answering player's own hand and public board state, excluding concealed opponent zones. Exact native `PokemonCardList` objects are reconstituted inside the adapter only after the pure owner decision.
- Supports `options.min===1` and `max===1`, mandatory or cancel-permitted, on either physical seat. A genuine `AddPlayerAction` identifies live `Store.state`; detached speculative states cannot earn an actor decision. The adapter creates a typed `ResolvePromptAction`, calls `assertValidPromptAction`, observes native dispatch, records accepted/rejected and separately marks postcondition confirmed/missing. Prototype overrides restore in `finally`.
- [Five actor-specific regression tests](../../tests/agent8-actor-only-choose-pokemon.test.cjs), commit `a54cb377611721eec005b32ce1c2fd984fca1082`: foreign perspective relative to the answering owner, blocked Bench slot, both seats' native typed dispatch fixture, cloned-State fallback, multi-target fallback, invalid-index rollback, optional empty-menu cancellation.
- Optional canonical integration in [existing composition](../../simulation/evaluation/agent7-canonical-actor-composition.cjs), commit `e1a133bb2d36ea716e598b00dc2a3a25f8a2203a`. Default behavior and previous five-component label stay unchanged.

## Open limitations / next validation

The deterministic first-valid-target policy proves a selected legal target exists in its detached menu but does **not** optimize gust targets, damage, Prize race, defensive pivots, upcoming attacks, resource tradeoffs, or opponent strategy. It handles only singleton `ChoosePokemonPrompt`, leaving multi-target and all non-owner-selection prompts to the unqualified fallback. The prior six fallback **invocations** may represent fewer than six independent decisions; no fresh count is known.

The next permitted compiled canonical manual run should use `actor_choose_pokemon=true` with the previous source-dealt four historical cells, optionally the four source-first stress cells. The archive should include complete eligible prompts by physical seat, native Store resolution proof, 0/6 estimated vs observed fallback *invocation* delta with identical other flags, source-deal and root-action fingerprints, after/before public game state, and every rejected/censored attempt. If the policy changes gameplay, label it a versioned policy intervention rather than a read-only audit. A second unchanged default-off reference run on the same head can establish bounded historical parity. Do not count any retrospective seed as competitive.
