# Agent 6: prospective actual-start stratification after the 29 October scout

Evidence class: protocol design and exact conditional probability, not a new native game or a deck-strength estimate.

The preregistered 32-arm source scout recorded source-first in 26/32 game attempts, corresponding to 13/16 nominal seed cells paired across two candidates. All eight candidate-physical-B seed cells were source-first; candidate-physical-A contributed five source-first cells out of eight. Under a hypothetical independent fair 50:50 actual-start model, eight in eight same-direction starts have probability 1/256 (0.390625%), while 13 or more in sixteen have one-sided probability 697/65536 (1.06353759765625%). These are reference calculations, not p-values proving engine bias: player choice after the coin flip, pseudorandom consumption and source-deck construction can violate that model.

The existing `simulation/evaluation/aichi-setup-only-capture.cjs` already stops a pinned Store session at the first settled real turn and can capture `firstTurnEvidence` validated against the draw log. A predeclared *outcome-blind* intake can use only that receipt to fill each (source rank, physical candidate slot, actual starting side) cell with the first quota-satisfying prospective seeds. Candidate comparisons sharing a seed must have matching actual first-player receipts; mismatches, invalid setups and quota-full seed rejects must all be preserved. The queue of CSPRNG seeds must be committed before native preflight, and the accepted seed identities plus complete rejection ledger must be committed before *any* full-game outcomes are run. No hand, Prize, board or tactical outcome may influence selection.

A locally tested pure selector and four Node tests are available with this invocation, but no repository-native Store run or compiled CI has validated this proposed intake. First-turn strata are necessary for fair comparisons and do not establish paired source-deal equality, first-turn lock competence, full rules fidelity, clock fidelity or wins. The observed 29 October cohort remains unchanged, and the benchmark remains 29/32 source lists, zero competitively qualified games and no validated 99.5% deck.


## 29 October correction: when chooser policies differ

The same-starter paired acceptance requirement above **only applies if both candidate policies share the same frozen GO_FIRST choice rule**. The coin winner chooses first/second before opening seven cards are drawn. Denote source's preference for first by s, candidate's by c, and the coin winner by W. The actual source-first indicator is `W===source ? s : !c`. If s is false and c true, source is always second; if s true and c false, source is always first. An actual-start-balanced 2x2 sample is then impossible. If the candidate's start preferences differ, requiring same actual first player in both candidate arms preferentially drops one coin-winner group. For such policy comparisons, preregister and balance **coin-winner identity**, verify actual turn from the draw log separately, and accept that each candidate's own-deck policy can make its starting order differ. Preserve all attempts and original source-deal matching as distinct checks. No opening hidden cards or gameplay outcomes should be involved in seed intake.


### Distinct post-mulligan pairing correction

Agent39's [exact source-setup analysis](agent39-mulligan-posttreatment-source-alignment.md) demonstrates that candidate Basic count alters candidate mulligan frequency, which can legally alter source bonus draws/hand/deck/Bench **before** the first stable player-turn source-position digest. Champion and New Moon have different Basic counts. Therefore **do not filter unconditional intended-to-test outcomes on matching post-mulligan source-physical-deal fingerprints**: that criterion conditions on a potential consequence of candidate choice. The initial source randomization input may be paired and audited **before** optional mulligan compensation; post-setup source digests, candidate/source mulligan counts and optional bonus draws must be reported as outcomes/diagnostics. Identical post-setup states remain useful for a separately labeled matched-position mechanical counterfactual only. The corrected coin-winner selector `simulation/evaluation/agent6-coin-winner-strata.cjs` does not require matching post-setup fingerprint; however, any subsequent intake that adds such a requirement would reintroduce selection bias. This distinction also applies if candidate choice policies yield different actual starting turns.


### Reconstructed source-first imbalance, using the original frozen seed tape

[The subsequent exact 16-seed audit](agent6-scout-start-order-seed-explanation-20261029.md) reproduces the 26/32 source-first observations using the first xorshift32 coin draw of every precommitted seed and the pinned generic confirm resolver's winner-chooses-second response. Group counts are rank6 candidate-A 3/4, candidate-B 4/4, rank11 candidate-A 2/4, candidate-B 4/4; doubled across both candidates = 26/32. Thus the reported skew has a transparent **realized-seed mechanism**, rather than requiring an unexplained Twinleaf coin bug or opponent-related hidden information. The small exact one-sided fair-cohort reference probability remains a description of an unusual sample, not an engine bias verdict.
