# Issue #25: pinned generic SimpleTacticsAi has a source-level hidden-order dependency

**Agent 8, 4 November 2026. Static source audit, not a native noninterference experiment.** Exact upstream pin: `a9905a76a6c4103ba4b6cb9a49e86bad795c5c05` under `vendor/twinleaf`. This report diagnoses the inherited scorer's design. Earlier compiled native counterexamples already establish decision reversals on deliberately constructed information-equivalent states; those external tests are identified below. Neither this source audit nor those fixtures qualifies a tournament game.

## Source-grounded call chain

1. `simple-tactics-ai.ts` passes the **actual full `State`** to each `SimpleTactic.useTactic(state, player)` and accepts its evaluated actions.
2. `simple-tactics/simple-tactics.ts` implements `evaluateAction`: calls `simulateAction(state, action)`, creates `new Simulator(state, this.options.arbiter)`, dispatches the hypothetical action and automatically resolves all pending prompts. It then scores the **resulting hypothetical full state**, not a detached player-information state.
3. `simple-bot-definitions.ts` configures the scorer's arbiter with `flipMode: BotFlipMode.ALL_HEADS` and `shuffleMode: BotShuffleMode.NO_SHUFFLE`. These are the *bot's counterfactual scoring settings*, not evidence that real native games were actually shuffled that way.
4. `state-score/hand-score.ts` reads every card identity in the resulting owner's hand and awards identity-sensitive scores for type and whether a Pokémon can evolve. Thus a counterfactual draw can feed the *actual hidden future deck cards* into a present decision score. `simple-tactics/attack-tactic.ts` and `play-supporter-tactic.ts` explicitly use `evaluateAction` to compare choices.
5. Independently, `play-supporter-tactic.ts` writes `player.supporterTurn = state.turn` after choosing its hypothetical Supporter, before native Store acceptance. Agent20 already independently demonstrated the quota-state pollution in a real same-deal root; this audit identifies its unmodified upstream source.

The mechanism is a genuine information-set risk: owner observations exclude unrevealed deck order, even after a search identifies deck membership. Prior compiled native tests below have confirmed that the unrestricted bot's selected actions can depend on that order in constructed states. The remaining question is when the *actually executing selected bilateral policy* exposes this mechanism along authentic, naturally reached original-source games.

## Existing native reproduction, discovered during cross-agent review

This 4 November source report originally omitted stronger previously published evidence. The executable [full-policy comparator](../../simulation/twinleaf/hidden-order-full-policy-audit.cjs) and [two-world fixture](../../simulation/twinleaf/hidden-deck-order-audit.cjs) are present in the repository and invoked by the existing manual-only `twinleaf-hidden-order.yml` workflow. This establishes at least one concrete default-bot native decision leak; it is stronger than the source-only mechanism proved here.

[Agent 9's original-rank-5 inventory counterexample](../twinleaf/agent9-rank5-native-fallback-concealed-order-release-veto-20261103.md) is more relevant to the current fallback integration. Its two injected states conserve the **same authenticated 60 printed cards**, preserve owner-observable zones, and move a Guzma below or inside the unseen top-four Trainers' Mail search window. Compiled [CI 41656269386](https://github.com/FlareZ123/experiment-01/actions/runs/41656269386) reports sixteen matched policy-randomness seed pairs with the same native Mail-versus-Pass reversal, which transfers through the default-off generic Trainer fallback classifier. These are engineered contrasts on one original source inventory, never sixteen organic matches or a leak-frequency estimate. There is still no demonstrated natural rank-5 Store root where this contrast changes the chosen action.

## Smallest release-gate falsification

Use the existing Agent4 outer native raw-decoder quarantine as the strict control, rather than implicitly accepting generic fallback decisions. Freeze one genuinely owner-visible eligible draw/Supporter choice. Construct a matched pair of actual engine states identical in owner-visible hand and both public boards, same legal actions, same counts and engine/randomness, but permute *unrevealed owner deck order* at K0. Observe any differences in proposed native root/prompt actions and StateScore. Repeat with concealed opponent-hand/deck identities altered but counts constant. A changed decision identifies a concrete breach; invariance on a narrow witness does not certify all tactics. Test both physical seats, failed Store proposals and restoration. For any policy that deliberately uses known owner-deck membership after K1, preserve provenance separately from still-concealed order.

**Release implication:** a stack of owner-safe interceptors cannot establish whole-policy information safety if unmodified generic fallbacks remain enabled. Either the executing closure explicitly quarantines that scorer or the release must directly prove its permitted information dependencies. Keep `hiddenInformationSafe:false` and `competitiveGameQualified:false` until the full selected policy passes Issue #25. The result is a source audit only, with zero additional native games or win-rate evidence.
