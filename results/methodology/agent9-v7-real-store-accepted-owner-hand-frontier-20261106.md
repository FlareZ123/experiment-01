## Decision-relevant result

An eight-attempt historical v7 original-source replay successfully repeated the previously archived **every accepted public root, disposition, root count and physical opening fingerprint** after adding actor-owned hand telemetry. Five previously verified original rank-6 **Volt Cyclone** settlements had subsequent real owner turns that ended in a genuine accepted **PassTurnAction**. The updated observer matched each of those five Passes to the *identical native action object* successfully dispatched through the registered real Store, and each to a *unique* accepted public Pass root. Thus all five owner-hand snapshots were actually observed at the real source-owner decision, rather than inferred from the printed 60 or a speculative bot Store.

**All five** authenticated source-owner Pass decisions held **Guzma BUS** (1–3 copies), had used **zero Supporters** that turn, and had both an occupied source Bench and an occupied opposing Bench. The native player restrictions in the observer show no Supporter play lock; these public states meet the ordinary printed Guzma switch prerequisites (opponent's Benched Pokémon and own Benched Pokémon). This is a **concrete owner decision opportunity**, with genuine Store acceptance and strategic benefit of a *Guzma attempt* still untested. It does not imply that switching would improve the position, recover an attack, or win a game. A switch could be strategically harmful.

The separate conservative necessary-resource screen found **zero** of these five positions met its narrow direct funded **Volt Cyclone** continuation conditions: no held Double Colorless Energy at any Pass; the two first-opening states had a DCE on a Benched Iron Thorns ex but no Thunder Mountain in play; the other three had Thunder Mountain but no funded DCE Bench target. Thus the absence of a repeat attack cannot be treated as a proved bot error. The relevant open comparison is whether proactive legal disruption, resource access, board positioning, or turn-ending is strongest at each owner root.

## First held-opponent counter-response check: Float Stone is already in the other hand

The same read-only observer records each player's own hand only on that player's real turn. In `6:201:B:champion-reference`, after source **Pass root32** on turn5, the opponent's actual turn6 actor-owned hand contains `Float Stone BKT`, `Mysterious Treasure FLI`, `Quick Ball FST`, `Battle Compressor PHF`, `Night Stretcher ASC`, and `Psychic Energy MEE`. The very same `Float Stone` is already observed in that opponent's hand on its preceding turn4, before the source canary. This observation is **post-hoc opposing-owner evidence**. The source bot's selected action must never read the opposing hand.

Printed `Float Stone` (BREAKthrough, `xy8-137`) says the attached Pokémon **has no Retreat Cost**. The opponent's original lone Benched `Marshadow UNB` has no Tool attached. If Guzma brings it Active, an opposing player holding Float Stone may be able to attach it and freely retreat back to Tapu Lele-GX on their next turn, provided no additional lock prevents the play or retreat. The v7 public source board has no Item or Tool play lock. This is a **concrete adverse-response candidate**, with native Store acceptance and resulting attack still untested. An opponent bot that leaves Marshadow stranded despite holding Float Stone would understate the strength of that counter-response, so a successful Guzma treatment must be evaluated against Tool-aware replies.

Thus the new owner-hand evidence gives both an accessible source gust alternative and a specific opponent-held counter. The controlled experiment should retain the opponent's action policy and identify its actual next consequential move, with a separate appropriate counterplay canary if it overlooks Float Stone.

## Proof boundary and regression correction

The original native observer recorded a proposed `PassTurnAction` using actor-only detached hand and public boards, but the join matched proposals by owner seat and turn only. This would have allowed a rejected or replaced proposal at the same turn to claim the hand seen at the accepted Pass.

**New implemented admission:** `simulation/twinleaf/agent9-v7-real-owner-decision-observer.cjs` uses a per-match WeakMap keyed by the *exact action object* returned by the real owner's `SimpleTacticsAi.decodeNextAction`. Its Store wrapper only marks the proposal accepted after `oldDispatch` returns successfully for the registered real Store and matching seat/turn, with no unresolved prompt. `scripts/agent9-v7-real-owner-observation-join.cjs` additionally requires exactly one identity-accepted native Pass proposal and one actual accepted public owner Pass root in the corresponding next source turn. On missing, rejected, speculative, ambiguous or unmatched actions, the join withholds private owner hand and the resource screen; it keeps all original failures and registered attempts.

Updated dedicated regression tests cover the original success path, ignored speculative Store, rejected Store action, replaced action, unaccepted proposal, duplicate proposals, missing public Pass, and multiple public Pass roots. A Store-accepted action is **not automatically paper-legal**, and the screen's necessary checks are never a treatment outcome.

## What changes in the research agenda

A source-owner next-turn Pass is now supported by a real hand, which permits specific *paper prerequisite* comparisons with other candidate actions. The existing generic player can Pass while holding a Supporter and an apparent gust opportunity. This finding justifies a **single registered owner-only same-root paper-paid Guzma A/B/A canary** on these actual opening states, with unchanged historical printed 60s and strictly identical preceding public roots, rather than assuming Pass was optimal or executing broad root-count races. The native Store must accept both target-switch prompts, preserve owner quota and physical board custody, and demonstrate whether the opponent's next consequential action and the owner's subsequent turn differ. Separate owner choice and competing use of the same Supporter need to be evaluated before promoting any policy into the common release.

A shared-development next step can compare first return `6:201:B:champion-reference` source turn5 root32 and first `6:200:A:champion-reference` source turn16 root65, using a registered treatment on *both seats* where possible. Preserve no-attack and rejected branches as outcomes. The current five hand observations do not show an automatic improvement from gusting.
