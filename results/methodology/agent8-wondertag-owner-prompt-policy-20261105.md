## Submitted bounded policy

[Owner-bound prompt adapter](../../simulation/twinleaf/agent8-owner-wondertag-prompt.cjs) wraps the **exact Tapu Lele-GX GRI PlayPokemonEffect** to mark only the actual Confirm and owner-deck Supporter-search prompt instances. During the genuine Confirm prompt it submits an affirmative ResolvePromptAction. **Only after the native owner-deck search prompt exists** does it inspect eligible Supporter objects in that already-searchable owner deck and submit the first valid one or the permitted empty selection. It calls the existing strict assertValidPromptAction before dispatch. Existing native Store dispatch is preserved and selected accepted/rejected actions counted by physical seat. Other prompts delegate to the previous policy, so full-policy hidden-information safety remains explicitly false.

The default first valid Supporter rule is a minimal source-independent liveness baseline. Version 2 introduced an optional `selectSupporterIndex({globalTurn,choices})` callback, which receives only the public turn number and a frozen array of Supporter names/printings **after the native owner-deck search is open**. It returns the offered index, or `-1` for a legal zero selection. An invalid or unoffered index fails closed before the native Store receives a selection. This supports future state-aware Supporter choice research without exposing either player's hidden zones or passing the full Store state to the selector. The default native fixture still selects the first eligible Supporter; no tactical superiority is established. It is **not** claimed to be matchup-optimal. It does not read opponent private zones, inspect unrevealed owner-deck order before the search opens, or independently access Prize faces. The exact post-search deck composition is allowed information during a real deck search by Rulebook I-H. The hook is reversible and stays outside upstream vendor/twinleaf. The independent zero-choice shuffle repair must be installed separately if those actions are admitted.

## Exact original-rank-11 opener exposure, a decision opportunity only

The authenticated original rank-11 Absol/Garbodor name/count 60 contains **eleven Basic Pokémon**: one Tapu Lele-GX, one Crobat V (a second on-play Bench trigger), nine other Basics, plus two Stage-1 Garbodor. Its eight Supporters are three Carmine, three Marnie and two Guzma. This is a frozen source-inventory count, not a print-art authentication or observed game frequency.

Under an independent uniformly random initial seven, conditional on at least one legal Basic (exact denominator `C(60,7)-C(49,7)=300,306,336`):

- The probability of **Lele plus at least one nontrigger Basic** in the opening seven is exactly `29,166,774 / 300,306,336 = 9.7123405%`. Such hands permit the *choice* of preserving Lele through setup while putting a different, nontrigger Basic Active.
- The stricter event of **Lele plus at least two nontrigger Basics**, permitting a nontrigger Active and a nontrigger starting Bench backup, has `10,097,934 / 300,306,336 = 3.3625444%`.
- Lele as the **sole Basic** in the seven has `13,983,816 / 300,306,336 = 4.6565171%`. In that event, preserving Lele is impossible under normal basic setup rules, illustrating the denominator distinction.

The first event has numerator `C(59,6)-C(50,6)`. For all full 7-hand/6-Prize physical deals satisfying the first event, exhaustive multivariate counting of the eight Supporters gives only `72,941,400 / 669,595,630,769,520 = 0.00001089335%` probability that **none** of those Supporters remains in the 47-card deck. For a target-specific search, rank 11 has two Guzma. Given the same Lele-plus-nontrigger initial-seven condition, a 6-Prize combinatorial count gives probability 23,466,973,854,240 / 669,595,630,769,520 = 3.5046486% that both Guzma are absent from the remaining 47-card deck. The disjoint cases are both Prized (0.8963295%), one in opening hand and one Prized (1.9211330%), or both in opening hand (0.6871860%). Hand-held Guzma is still usable, so absence from the deck is not absence from play. The distinction shows why searching some Supporter says little about target-specific gust access or Prize recovery; a tactical selector needs real-state testing.

This is mathematical availability, not a forecast of actual ability use: the chosen setup, active locks, Bench geometry, turn state, reward quality, owner strategy and possible other Supporter access are all excluded. It is also source-11-specific, not a claim about the missing three Top-32 decks. This refines the broader previously published rank-11 **18.5338% both-trigger-card opening opportunity**, which counts Crobat-only as well as Lele openings.

**Native dispatcher audit hardening (5 November, source verified).** Pinned Twinleaf `Store.reducePrompt` can return its state unchanged when the prompt ID has no pending `promptItem`, without throwing. Therefore a raw `Store.dispatch` return value is insufficient proof that a selected prompt settled. Adapter v3 now requires identity-equal native `prompt.result` after dispatch. For a positive Supporter search it separately checks that the **exact physical chosen card** left the owner's deck and entered the owner's hand before incrementing accepted or selected-transfer counts. Two additional **local mock negative tests** exercise a silent no-op and a resolved prompt with missing physical transfer; both fail closed with separate audit counters. Compiled native regression remains pending. These tests strengthen **action receipt validity**, not whole-game competence or paper legality.

Version 4 additionally requires an affirmative Wonder Tag `ConfirmPrompt` to have generated an **actual unresolved owner-targeted Supporter `ChooseCardsPrompt`** before incrementing the confirmed-action count. A mock that marked Confirm resolved without invoking its callback fails this gate; all **15** local pure tests pass. This matters because successfully dispatching an action and changing a prompt result are insufficient evidence that its intended card-specific action actually occurred. It is still a mock-level falsifier pending compiled source test.

The generic owner-modal fallback currently declines optional Confirm prompts. Two additional locally executed mocked wrapper-precedence regressions prove that installing generic modal first and exact Wonder Tag decoder second gives the source-bound `true` response, whereas the reverse order shadows the exact handler and yields `false`. This establishes the composition precedence mechanically for the mocks. A full v14/v15 native A/B/A test is still required to prove the actual selected stack uses the intended order.
