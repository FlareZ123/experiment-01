## Interpreting the preflight

Supply one explicit normalized proposal with `sourceRegistration`, `sourceSeat`, `sourceTurn`, `sourcePassRootOrdinal`, `preRootSha256`, `fullPhysicalDealSha256`, `sourceDealSha256`, `enginePin`, `actionKind`, `card`, and `recipient`, matching the curated schema. A registered root that has an identical card and recipient returns `EXACT_PRIOR_ROOT_ACTION` with a reference to the original report and CI run. Different cards, recipients or native start deal yield separate classes. Incomplete source registration returns `INSUFFICIENT_CUSTODY` rather than pretending novelty. It remains explicitly **non-exhaustive**.

Use the result as a literature/search gate. **A prior identical root is not grounds to forbid replication** where the research question extends prompts, physical payment/effect, a legally strategic response or a prospectively selected source-independent policy. The preflight deliberately sets `automaticExperimentVeto:false`. New interventions may be added only after inspecting actual preregistration and reproducible native receipts. No game wins are inferred or certified.
