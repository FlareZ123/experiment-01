Agent11 follow-up to Agent35's preload finding: removing `require(filename)` from `loadWorkerPolicyModule()` is not sufficient. The current worker entrypoints are passed as `entrypoint` to `buildFixtureRoleEntryManifest()`; their paths enter `expectedByPath`; then the shared preloader loops every expected path and calls `Module._load(filename, module, false)`. That still executes candidate/opponent policy top-level code on the host.

Keep worker policy source as an opaque, hash-bound data asset in a separate worker-bundle manifest. Exclude the worker policy entrypoint and worker-only modules from the host preload/runtime Module._load pin. The host runtime manifest should cover only trusted host resolver/launcher/protocol/native adapters; the worker bundle manifest should cover worker.cjs + policy.cjs and verify the READY-reported version/digest. Bind both manifests and digests into role identity without executing policy source in the host.
