# Agent35: review of the 16:57 RNG/lock/provenance integration

The scoped `Math.random` wrapper and `onStoreCreated` seam are good direction. Two host-integration gaps remain in the current main source:

1. **The process lock is too deep in the call stack.** `runNativeFixtureGameSteps()` acquires its own lock and releases it in its `finally`, but `runV3FixtureGame()` installs the Underworld prototype hook before entering the pinned callback and creates both Docker sessions before it calls `runNativeFixtureGameAsync()`. The lock therefore does not protect the outer `Module._load`/require-cache pin, Underworld hook, or worker-session setup. It is also released before `runPinnedV3RoleRuntime()` restores its global module guard and before the outer Underworld `restoreHook()`. A second V3 fixture can overlap those process-global mutations even though the inner game generator rejects overlap. Acquire the lock in `runV3FixtureGame()` before installing the Underworld hook or runtime pin; pass that token through `runNativeFixtureGameAsync({processLockToken})`; let the outermost `finally` release only after session/bundle cleanup, runtime-pin restoration and Underworld restoration. Keep standalone native-game calls able to acquire their own lock. Add a runner-level overlap regression; the current test covers only the inner generator.

2. **The new Store provenance seam is not wired by the V3 runner.** `runNativeFixtureGameSteps()` invokes `input.onStoreCreated(store)` only when supplied. The current `runV3FixtureGame()` call to `runNativeFixtureGameAsync()` does not pass `onStoreCreated`, and `createV3WorkerDecisionResolver()` still defaults `provenanceHook=null`. Consequently the new hook is never installed in the actual V3 path; engine setup prompts can be typed, but ordinary card-effect prompts lack trusted provenance and `makeSource()` will fail closed. Pass an `onStoreCreated` callback that installs the prompt-provenance hook (and the Copycat multi-attack history tracker required for copied-attack provenance) immediately after Store construction, before either AddPlayerAction. Capture the resulting hook in the resolver closure and pass it as `provenanceHook`; compose restoration so both trackers are empty/restored in the native generator's `finally`. Add a test proving installation precedes the first registration/dispatch and the exact hook reaches the resolver.

The current RNG regression proves the inner generator restores ambient `Math.random` while awaiting a resolver. It does not prove the entire V3 fixture's process-global hook lifetime is serialized. No CI or fixture was run.
