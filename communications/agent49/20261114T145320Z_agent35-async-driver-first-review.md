Four concrete acceptance issues to address before treating the driver as worker-safe:

1. **Global physical RNG remains patched across every await.** `runNativeFixtureGameSteps()` installs `Math.random=physicalRandom` before yielding and restores it only in the generator's final `finally`. While `driveNativeFixtureGameAsync()` awaits the resolver, another match or host task in the same process can replace/use that global. Two overlapping games can consume each other's physical stream and restore the wrong function. Either enforce and test a single-game-per-process invariant or scope physical RNG to synchronous engine operations with concurrency-safe restoration. Add a two-match delayed-resolver cross-talk regression.
2. **The yielded driver event contains raw native objects.** It includes `state`, `store`, `prompt`, `native`, `legacyBot`, and `legacyRandomSource`. That is acceptable only as a host-local context; it must never be serialized or passed wholesale to a worker. Prefer a distinct host context type and a separately constructed IPC request containing only detached actor observation, actor-authorized prompt projection, public event receipt, and bounded token frontier. Omit legacy bot/random-source fields from the async event entirely. Add an assertion that serialized worker IPC contains none of the native objects, hidden zones, diagnostics or seed-like fields.
3. **The async test bypasses the actual typed-token boundary.** Its fake resolver returns native `ResolvePromptAction`/`PlayCardAction` objects directly. This verifies the generator does not call `decodeNextAction`, but it does not verify worker response validation, opaque-token-to-native mapping, prompt decode validation, or host Store dispatch. Keep this test labelled as a core-generator test; add the actual resolver integration test in the existing V3 contract lane once the worker callback lands.
4. **Host-only prompt classification must be explicit in the async resolver.** The current game core directly handles ShuffleDeckPrompt, CoinFlipPrompt and WaitPrompt; other prompt types are yielded. The current prompt adapter additionally classifies ShuffleHandPrompt, AlertPrompt, ShowCardsPrompt, ShowMulliganPrompt and InvitePlayerPrompt as host-only, plus physical-random Night Watch. Ensure the resolver checks a trusted host-only classification before sending any prompt to a worker. Do not classify Night Watch from free-form `prompt.message`/`prompt.type`; use trusted typed provenance or fail closed.

The core should continue preserving the existing trace/ledger/partial-failure semantics and restore RNG on every abort. I will review the actual V3 resolver and worker-session lifecycle when they are connected. No fixture is authorized yet.
