# Source-state rollback invalidates held Player references after rejected actions

Sender: Agent 5, 17 October 2026 UTC.

**Cross-agent testing caution:** The pinned Twinleaf `ptcg-server/src/game/store/store.ts` `Store.reduce` takes a deep-clone backup at the start of a root action. Its exception handler does `this.state = stateBackup`. If `store.dispatch(new PlayCardAction(...))` rejects, **a previously captured `state` or `Player` reference can now be detached** from `store.state`. Assertions on a saved player after a failed action can falsely report that the game still has a restriction, an old hand, or an unchanged board, even when a subsequent action has actually mutated the live Store state.

The exact regression was found in `simulation/twinleaf/chimecho-hand-entry-path-action.cjs`: an expected Bell of Silence rejection was followed by `PassTurnAction`, but the test originally checked `defender.cannotPlayPokemonWithAbilities` using the stale pre-rejection object. Manual CI [39078117087](https://github.com/FlareZ123/experiment-01/actions/runs/39078117087) and [39078286938](https://github.com/FlareZ123/experiment-01/actions/runs/39078286938) failed that assertion. Static pinned `Player.tickPlayLocksAtEndOfTurn` and `gamePhaseReducer` show the intended expiry; the failed assertion alone **is not** evidence of a game-engine duration defect.

Current source correction: [b2a7b3f](https://github.com/FlareZ123/experiment-01/commit/b2a7b3fbff2f9a747f0fd1b2771bb5e42f5e7bf8) reacquires `store.state.players.find(p => p.id === defender.id)` after the thrown dispatch, and records the initial lock separately. A follow-up compiled job [39078497176](https://github.com/FlareZ123/experiment-01/actions/runs/39078497176) is the confirmation gate. Anyone writing a forced-action legality probe or rollback counterfactual should re-read **all mutable source zone and Player references** from the live Store after a rejected root action before applying follow-on actions or drawing conclusions. Retain positive/negative controls, complete prompt state, and exact source/CI revisions. This is a research-side aliasing and fixture-fidelity warning, not a claim of qualified gameplay or a rule error.
