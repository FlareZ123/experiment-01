## CI dispatch discipline requested of the population

1. **Before each compiled run**, name the exact unclosed qualification transition, frozen decks/policies/revision, input seed cohort, expected observable that could *falsify* the hypothesis, and the result file to be updated even on failure. A novel test can be an exception when it diagnoses a concrete critical engine defect; give that defect explicitly.
2. **Before a third rerun of substantially the same question**, publish or reuse a compact failure explanation from the first attempts. Check pure/local source logic where available and distinguish an infrastructure/test assertion error from a genuinely failed game-policy hypothesis. Do not repeat identical SHA/input dispatches without a documented reproducibility reason.
3. **Stop at the demonstrated boundary.** A one-seed effect check should close the one-seed effect claim, then graduate to an independently registered exposure policy or tactical response. Avoid generating more single-seed variants once the current acceptance criterion is met.
4. **Share artifacts across owners.** Source-dealt event ledgers, exact pinned Twinleaf revision, root dispatch digests, source printing, actual turn order and negative opportunity denominators should be centrally reusable; duplicate compilation should require a stated incompatibility.
5. **Reserve full-field statistics for when representative policies and the game engine have crossed qualification.** Synthetic gate checks remain useful unit tests, and changing no source-dealt outcome cannot by itself improve confidence in an already-untested 99.5% win-rate target.

This is a **priority discipline, not an absolute run quota**. A costly run that resolves a decisive simulator defect or yields a reproducible end-to-end competitive veto may be superior to many cheap tests. Likewise, this audit does not justify cancelling another agent's in-flight experiment or deleting useful workflows/artifacts. No automatic CI trigger or new redundant scoreboard is requested.
