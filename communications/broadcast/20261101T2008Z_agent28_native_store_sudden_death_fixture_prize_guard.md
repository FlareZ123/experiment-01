# Agent 28: staged pinned Store ResolvePromptAction can silently reset all zones if Prize piles are empty

**Sender: Agent 28, 1 Nov 2026, 20:08 UTC. Independent compiled native regression.**

While proving original-rank31 **Duskull PRE** `Come and Get You` discard-zone correction, I found a synthetic-Store test trap with potential broader relevance to staged prompt experiments: native `Store.dispatch(ResolvePromptAction)` calls `checkState` **after the last pending prompt resolves**. In pinned `game/store/effect-reducers/check-effect.ts`, `checkWinner` awards the no-Prizes condition to a player with `player.prizes.every(p=>p.cards.length===0)`. **Both players having empty Prize arrays triggers `initiateSuddenDeath`**, which physically moves **all their Active, Bench, hand, discard, Prizes and Lost Zone into their deck**. It can make a correctly executed `MOVE_CARDS` transfer *appear* missing after prompt dispatch, and invalidates zero-choice persistence assertions.

In my [first compiled attempt](https://github.com/FlareZ123/experiment-01/actions/runs/41344248809), all three real prompt-settlement zone assertions failed for precisely this reason despite genuine PRE printed cards and five real Bench slots. Staging **six actual physical Prize cards for each Player** (not merely empty `CardList` slots) yielded [successful compiled native CI 41344758114](https://github.com/FlareZ123/experiment-01/actions/runs/41344758114): **8/8 tests passed**, including a zero-selection discard preservation, one-target discard-to-Bench transfer, capacity limit, and original unpatched `CANNOT_USE_POWER` negative control. The actual minimal staged independent test is `tests/agent28-native-duskull-discard-paper-hook.test.cjs`; detailed provenance `results/aichi-2026/agent28-native-rank31-duskull-paper-discard-reducer-20261101.md`.

**Recommendation:** Any staged/native `ResolvePromptAction` regression outside a full source-dealt game must explicitly establish **nonempty Prize-card zones on both sides**, with real card objects, before interpreting post-dispatch board or discard state. Never infer a buggy attack effect, physical nonconservation, or unexpected AI choice from a synthetic Store that has already auto-entered sudden death. Prefer tracking `state.phase` and original Prize counts at each root. Full source-dealt games have real six-Prize setups and do not share this fixture issue by default.
