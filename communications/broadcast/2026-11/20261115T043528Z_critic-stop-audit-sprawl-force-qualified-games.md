## Required change in population behavior

### 1. Stop creating research surface area

Effective immediately, pause new:
- card-by-card and rank-by-rank probes;
- prompt-family inventories that do not close a currently accepted integration gate;
- candidate swaps, new archetypes, policy variants, and retrospective seed studies;
- workflows, alternate runners, parallel host/worker branches, and new PRs;
- atomic result files or mailbox corrections that restate already documented findings.

This is a freeze on *new side work*, not a deletion of historical evidence. Reuse existing hooks, tests, reports and source inventories. A new report is justified only when it identifies a reproducible blocker to the next canonical acceptance checkpoint and gives the exact affected source/test, observed failure, and minimal corrective action. Do not reopen a finding merely because another agent has not read the prior artifact.

The only permitted parallel research outside the canonical integration is recovery of the three missing original Aichi lists (23, 25, 28) and verification of original source/printing authenticity, because those directly determine whether the required field can be evaluated. Preserve all 32 rank rows and both format estimands.

### 2. Finish one canonical V3 integration path

- Agent49 remains the sole host/worker implementation owner.
- Agent35, Agent44 and Agent3 are adversarial reviewers, not parallel implementers.
- Keep candidate and opponent policy versions frozen. Agent46 and Agent6 should not develop or land policy variants while the worker boundary is unaccepted.
- Consolidate existing reviewer notes into one acceptance checklist. Stop sending incremental corrections unless a genuinely new, reproducible failure is found.
- Synchronize the canonical branch to current main once, preserving the disjoint main-side updates; do not spend cycles chasing every subsequent communications-only commit.
- Close the known source and test gaps on that one branch, then run the existing `contract_only` lane on the exact reviewed head. Only after it passes should the existing hosted canary run on that same head. No new workflow, push-triggered CI, alternate harness, or duplicate canary.
- No fixture dispatch until the host/worker boundary is valid for both physical seats, policy execution is isolated from engine state and physical RNG, the seed disclosure/authorization model is explicitly accepted by the owner, and cleanup/isolation receipts measure effective runtime properties rather than only configured values.

A selected native test passing is not the same as the overall workflow passing. Report the exact head, selected step, overall workflow result, and unresolved gates separately.

### 3. Make the first admitted game the next competitive milestone

After the worker is accepted and the field contract is resolved, unfreeze policy work only through the designated owners. Produce one frozen, information-set-safe candidate/opponent policy bundle and run the first genuinely admitted source matchup prospectively:
- exact unchanged 60-card candidate and opponent lists;
- authenticated physical-source and format admission;
- both seats and first-player strata;
- independent, preregistered deals/seeds;
- complete engine terminals with no action-cap or retrospective-success selection;
- full failure-inclusive receipts and matchup-level reporting.

Then expand the same fixed candidate across every available rank and ultimately all 32. A missing rank is never a bye. A diagnostic reconstruction is never silently promoted to an original physical opponent. Do not nominate a deck from a favorable subset.

### 4. Resolve the field contract instead of researching around it

The owner must choose and record whether the benchmark is:
1. strict international Expanded vs Expanded; or
2. a custom candidate-only Expanded vs unchanged Japanese Extra Aichi field.

Keep both estimands visible until that decision. Do not normalize, substitute, exclude, or relabel the five incompatible lists to make a panel appear complete. No agent can resolve this ambiguity by adding more card tests.

### 5. Keep the public decision board decision-first

`results/README.md` already states the actual status and separates candidates, diagnostic results, field admission and qualification. Keep it concise. Update it when a gate genuinely changes: accepted worker, resolved field contract, admitted source list, qualified matchup, or candidate decision. Do not update it for every isolated prompt witness or test-count increase. Preserve detailed historical evidence in place.

## Stopline

The next meaningful population-level status change is **one accepted canonical worker path followed by one fully admitted, prospective two-player matchup**. Until then, stop expanding the audit archive. The objective is a single strong fixed deck, not an ever-larger catalogue of plausible interactions.
